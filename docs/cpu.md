# CPU 性能检测（`cpu.sysbench`、`cpu.geekbench`）

[返回文档目录](README.md) | [简体中文首页](../README.zh-CN.md)

CPU 章节包含两项互补的插件：**`cpu.sysbench`** 提供轻量、可离线重现的整数素数吞吐率与多核扩展比测试；**`cpu.geekbench`** 运行业界通用的 Geekbench 7 综合工作负载套件，衡量真实应用场景下的单核与多核表现。

---

## 1. CPU 基础算力：`cpu.sysbench`

| 属性 | 说明 |
|---|---|
| 插件 ID | `cpu.sysbench`（所属分组：`cpu`） |
| 适用平台 | 独立服务器、虚拟机、容器（全平台） |
| 依赖工具 | 静态构建 `sysbench 1.0.20`（自动下载并校验 SHA-256） |
| 网络要求 | 无（工具下载完成后无需外网连接） |
| 超时上限 | `10 分钟` |
| 配置表 | 无自定义配置项（固定标准参数以确保跨机器横向可比） |

### 测试逻辑
1. **标准参数**：执行 `sysbench cpu --cpu-max-prime=10000 --time=20 --threads=<N> run`，统计每秒完成的素数筛查事件数（`events per second`）。
2. **单核与满核两阶段**：
   - 第一轮固定使用 **1 个线程**运行 20 秒，完成后立即向编排器发布单核阶段结果。
   - 当主机可用线程数 `N > 1`（容器内按 cpuset 限制计算）时，第二轮使用 **全部 `N` 个可用线程**运行 20 秒，并计算多核相对单核的加速倍率（`multi / single`）。
3. **容错重试**：若某次运行因瞬时异常退出或未输出速率，自动重试最多 **4 次**；若重试后成功，报告中会通过 `Note` 注明重试次数与上次失败原因。

## 2. Geekbench 7 综合基准：`cpu.geekbench`

| 属性 | 说明 |
|---|---|
| 插件 ID | `cpu.geekbench`（所属分组：`cpu`） |
| 适用平台 | 全平台（需满足 `glibc >= 2.35` 且具备 IPv4 公网连接） |
| 依赖工具 | 官方 `Geekbench 7.1.0`（`x86_64` 正式版 / `aarch64` Linux ARM Preview） |
| 网络要求 | **必须具备 IPv4**（`cdn.geekbench.com` 与成绩上传接口需要外网连接） |
| 超时上限 | `250 分钟` |
| 配置表 | 无自定义配置项（若不希望上传公开跑分记录，可使用 `--skip cpu.geekbench` 跳过） |

### 测试逻辑与小内存机器保护机制

Geekbench 7 工作集较大，在低配 VPS（如 1 GiB / 2 GiB 内存机型）上直接运行极易触发 Linux OOM Killer。`cpu.geekbench` 为此内置了完整的内存评估与保护流程：

1. **动态内存需求估算**：
   - 启动时实时读取 `/proc/meminfo`、容器 cgroup 剩余内存配额与测试目录所在分区的剩余磁盘空间。
   - 按经验公式估算峰值内存需求：`所需内存 = 1 GiB + 1 GiB × 可用线程数`（例如 1 核估算 2 GiB，4 核估算 5 GiB）。
2. **内核 Swap 有效性预判（MGLRU + `swappiness=0` 检测）**：
   - 在开启了 Linux Multi-Gen LRU（`/sys/kernel/mm/lru_gen/enabled` 第 0 位为 `1`）且 `vm.swappiness == 0` 的内核上，内核仅回收页缓存而绝不换出匿名进程内存，此时挂载 Swap 文件也无法防止 OOM。插件会主动识别这一组合，跳过无意义的磁盘写入并在报告备注中说明原因。
3. **自动创建与清理临时 Swap 文件**：
   - 当现有“可用内存 + 空闲 Swap”小于估算需求且内核会使用 Swap 时，插件计算缺口并向上取整至整数 GiB（最多补充 **8 GiB**，同时保证测试目录所在磁盘至少留出 **1 GiB** 剩余空间）。
   - 在插件专属工作目录下创建临时 `swapfile` 并启用，测试结束（无论成功、失败或 `Ctrl-C` 中断）后自动关闭并删除该文件；若卸载失败会在报告中明确打印残留路径与系统错误。
4. **OOM 优先级保护与精准死因诊断**：
   - 启动子进程时调整 OOM 优先级，确保万一物理内存与 Swap 仍耗尽，内核优先终止 `geekbench` 子进程而非 `lowendaff-bench` 主进程或宿主机关键服务。
   - 每次运行前后对比 `/proc/vmstat` 的 `oom_kill` 计数器：一旦检测到进程因 OOM 被杀，立即停止无意义重试并明确报告 `out of memory`。
5. **仅针对网络上传失败重试**：
   - 免费版 Geekbench 7 在跑分结束后必须将结果上传至 Geekbench Browser 以换取分数与公开链接。
   - 若计算阶段已完成、仅最后上传结果因网络抖动失败（尚未产生公开记录），插件最多重试运行 **4 次**；其他本地执行错误不盲目重跑，避免浪费数十分钟时间。
